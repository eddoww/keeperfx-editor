# Packaging

| File | Purpose |
|---|---|
| `org.keeperfx.MapEditor.desktop` | freedesktop launcher; `Exec=kfx-editor %f`, `MimeType=application/x-keeperfx-map` |
| `org.keeperfx.MapEditor.mime.xml` | shared-mime-info type for `map?????.slb` (install to `/usr/share/mime/packages/`) |
| `org.keeperfx.MapEditor.metainfo.xml` | AppStream metadata, declares the media type |
| `PKGBUILD` | Arch Linux package that builds from a local checkout of this repository (ships the `managed-install` marker, see below) |
| `windows.md` | Windows executables, icon resources, installer and signing notes |
| `windows/installer.iss` | Inno Setup script of the Windows installer |
| `windows/build-installer.ps1`, `windows/smoke-test-installer.ps1` | build and try the installer (used by the workflows) |
| `macos/Info.plist` | bundle metadata for `KeeperFX Map Editor.app` (the release workflow builds the unsigned bundle, with `icons/kfx-editor.icns`) |
| `icons/` | the application icon: PNG 16 to 1024 px, `kfx-editor.ico`, `kfx-editor.icns`, SVG; generated by `tools/make_icon.py` |

The desktop entry passes `desktop-file-validate`, and the MIME file compiles with
`update-mime-database`. `Icon=org.keeperfx.MapEditor` is found in the hicolor theme: install
`icons/kfx-editor-<N>.png` as `share/icons/hicolor/<N>x<N>/apps/org.keeperfx.MapEditor.png` (the
PKGBUILD does; the Linux release archive has them under `icons/hicolor`).

## Packages and self-update

The editor updates itself from the GitHub releases. A distribution package must turn that off:
ship a file named `managed-install` either next to the executable or, for an executable in
`<prefix>/bin`, as `<prefix>/share/kfx-editor/managed-install` (the PKGBUILD installs
`/usr/share/kfx-editor/managed-install`). The editor then only tells the user that a newer
version exists. A read-only install folder has the same effect, but the marker makes the reason
clear to the user. See `docs/manual/updates.md`.

The component id `org.keeperfx.MapEditor` follows the reverse-DNS convention of AppStream and
freedesktop. AppStream expects the id to belong to a domain the project controls; a distribution
that publishes the metadata in a store may need to change it.

## Release archives

`.github/workflows/release.yml` builds the archives attached to a GitHub release when a `v*` tag
is pushed: `kfx-editor-<tag>-linux-x86_64.tar.gz` (with the desktop entry and the MIME file),
`kfx-editor-<tag>-windows-x86_64.zip` (with `kfx-editor.exe` and `kfx-editor-cli.exe`) and the
installer `kfx-editor-<tag>-windows-x86_64-setup.exe`, and `kfx-editor-<tag>-macos-arm64.tar.gz`
and `-macos-x86_64.tar.gz` (with the executable and an unsigned application bundle). Each archive
holds one top folder with the README, changelog, licence, `THIRD_PARTY.md` and the user manual,
and `SHA256SUMS.txt` lists the SHA-256 checksum of every asset. The self-update relies on that
layout and on the sums file: an asset missing from `SHA256SUMS.txt` is never installed.

The tests a package build can run without game data are described in
[CONTRIBUTING.md](../CONTRIBUTING.md#testing).
